# Contributing to DOTA RUINER

Спасибо за желание улучшить проект. Приоритеты в порядке важности: достоверность аналитики, безопасность, стабильность, доступность, затем количество функций.

## Подготовка

```bash
npm ci
npx playwright install chromium
npm run check
```

Нужен Node.js 22+. Не добавляйте реальные ключи, `.env`, raw приватные match dumps или персональные данные.

## Изменение scoring

1. Проверьте, что поле действительно возвращается OpenDota для рассматриваемого типа матча. Отсутствующее поле должно быть `null`/unavailable, а не `0`.
2. Добавьте минимальный анонимизированный fixture в `tests/fixtures/` с описанием происхождения структуры поля.
3. Сначала добавьте падающий тест для нормализации и score-компонента.
4. Веса и thresholds меняйте только в `src/data/scoring-config.js`; не прячьте magic numbers в UI.
5. Объясните `observed`, `expected`, `available` и evidence. Никаких синтетических timeline и вероятностных процентов без валидированной вероятностной модели.
6. Если меняется смысл или сопоставимость оценки, увеличьте версию `ruin-v…` / `impact-v…`. Major-версии в сравнении считаются несопоставимыми.
7. Обновите README и тесты на demo, partial/unparsed, turbo, zero-kill и missing fields.

## UI и данные

- Пользовательские строки выводятся через `textContent`, DOM API или canvas text с лимитом длины — не через `innerHTML`.
- Новая интерактивность должна работать с клавиатуры, иметь видимый focus и цель не меньше 24×24 px (в проекте целимся в 44×44).
- Демо всегда явно помечается и не смешивается с реальной историей.
- Ошибка OpenDota не должна автоматически запускать демо.
- Для графика допустим только наблюдаемый временной ряд.

## Pull request checklist

- [ ] Есть тест, который падал до изменения.
- [ ] `npm run check` проходит локально.
- [ ] Нет serious/critical axe violations в затронутых состояниях.
- [ ] Нет реального API key или чувствительных данных (`git diff`, `rg`).
- [ ] Документация и версия модели обновлены при необходимости.
- [ ] Изменения проверены на desktop и mobile.

Небольшой PR с доказуемой метрикой лучше большого набора неподтверждённых коэффициентов.
